# T10 — Prisma schema and migrations

**Phase:** 2 · **Depends on:** T09 · **Size:** M

## Goal
The real database schema, including the Better Auth tables, kept as plain Prisma (no hand-written SQL beyond a couple of `CHECK`s).

## Read first
- `01-architecture.md` §3 (all of it)
- `04-code-style.md`
- The Better Auth docs: Prisma adapter, CLI schema generation, `user.additionalFields`
- The Prisma 7 docs: migrations, and custom SQL in a migration (`--create-only`)

## Deliverables
1. **`prisma/schema.prisma`:** implement the architecture §3 models and enums (drop the `HealthCheck` placeholder).
   - Use `npx @better-auth/cli generate` (or the current equivalent) to get the exact `Session`, `Account` and `Verification` models, then merge them in.
   - Keep the field names Better Auth expects, and map the extra user fields.
   - Use `@db.Date` for every calendar date.
   - Add a one-line `///` comment above each model and any non-obvious field, so the schema reads as documentation.
2. **Migration 1** (`init`): generated by Prisma.
3. **Migration 2** (`checks`): created with `--create-only` and edited by hand to add two simple `CHECK`s, each with a SQL comment:
   - `CHECK (extract(dow from "effectiveFrom") = 0)` on `WorkingPattern` (it must be a Sunday);
   - on `Event`, the start must not be after the end: `"startDate" < "endDate" OR ("startDate" = "endDate" AND NOT ("startHalf" = 'PM' AND "endHalf" = 'AM'))`.
   - Preferred-name length is checked by zod, not the DB.
4. **`lockUsers(tx, userIds)`** in `src/server/db.ts` (architecture §3.2): sort the ids, then one `tx.$executeRaw` `SELECT 1 FROM "User" WHERE id = ANY(${ids}) FOR UPDATE`. Add a two-line comment explaining why.
5. **Mapping helpers** in `src/server/mappers.ts`: Prisma rows → domain types (`Booking`, `PatternVersion`, `Override`, `PublicHoliday`), using `fromDbDate` / `toDbDate` from T05. This is the **only** place Prisma types meet domain types. A `WorkingPattern` row's `sun … sat` columns become the domain's 7-item `WeeklyPattern` list (`[row.sun, row.mon, …, row.sat]`), and back for writes.
6. **Replace the T02 placeholder:** delete the `HealthCheck` model and the T02 `init` migration (nothing is deployed yet), and restart the in-memory test DB (`docker compose restart db-test`) so `migrate deploy` starts clean.

## Tests (integration)
- `lockUsers`: two transactions locking the same user run one after the other (the second waits); different users don't block each other.
- The `Event` start/end check rejects a backwards range.
- Deleting a user cascades their events, patterns, overrides and exclusions, and sets `createdById` to null on other people's events.
- Deleting a team sets members' `teamId` to null (and the service in T29 does it explicitly too).
- A `WorkingPattern` with a non-Sunday `effectiveFrom` is rejected.
- A round-trip test for the mappers (date fidelity across DST).

## Acceptance criteria
- `pnpm db:reset` applies all migrations cleanly, and `prisma migrate diff` shows no drift.
- Integration tests pass in CI.

## Out of scope
Seed data (T13), services, and the overlap check itself (T22, using `lockUsers` + `findConflicts`).
